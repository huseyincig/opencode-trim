## 2. Defects found and fixed

| # | Defect | Impact | Fix | Regression test |
| --- | --- | --- | --- | --- |
| 1 | Saving a new cache identity replaced the session entry, discarding `plannedDrops` | Old results resurrected after any model/tool/system change; repeated prefix rewrites | `ContextCache.begin` keeps the committed set and only admits new decisions | `committed drops survive a provider-identity change` |
| 2 | Prune keys included message/part indexes | Keys changed after an insert/compaction, so replay was lost | Key = tool + call id + content fingerprint + owning message id | `planned drops replay after a message is inserted before them` |
| 3 | Read supersession required exact `offset/limit` equality | A later wider read did not supersede an earlier narrower one | Range-coverage evidence: later start ≤ earlier start and later end ≥ earlier end | `a later read supersedes an earlier slice only when it covers the range` |
| 4 | Shell results with a second text part (exit/timeout notice) were skipped entirely | Large/failed shell outputs never compressed | Compress each text part; keep notices byte-identical; mirror `output.output` only when it equals the first part | `multi-part shell result …` |
| 5 | `exitCode` lookup missed V2's `result.output.exitCode` / `metadata.exit` | Failure classification could be wrong | Added both locations with safe-integer checks | multipart/exit test + family suite |
| 6 | `\bE[A-Z]{3,}\b` under `/i` matched ordinary words ("example") | Most text was falsely "diagnostic", blocking compression | Numeric `E\d{3,}` only; wording already catches `Error:` codes | 24-family end-to-end suite |
| 7 | `SUMMARY` matched `1 test` inside passing-row names | Family candidates and preservation checks rejected valid pruning | Line-anchored summary grammar; counts kept for `passed/failed/errors/warnings` | dispatch + existing precision tests |
| 8 | Token-tail protection used `JSON.stringify` on host message classes | Cyclic host messages protected *all* entries, silently disabling pruning | Safe field walker with no stringify; media gets a conservative 4000-token weight | real-host pruning run |
| 9 | No pressure limit for custom providers absent from `ctx.model.list()` | Pruning never became pressure-aware for such providers | Explicit `contextWindow` option (default 0/off), used only when event/catalog lack a limit | `explicit contextWindow is a last-resort pressure fallback` |
| 10 | Mixed text+media results could be partially rewritten | Payload desynchronization risk | Whole result rejected when any non-text part exists | `mixed text/media results … untouched` |
| 11 | Family dispatch did not exist; only 4 coarse kinds | Per-command family behaviour was absent | 24 family modules + central verification gate | `test/families-dispatch.test.mjs` (26 cases) |

## 4g. Optional memory module — Phase 1, default off (2026-11-15)

As-built status: optional, default OFF. Package remained `0.3.0` experimental with no version bump, tag, release or publish for this addition (0.4.0 final in §0).

**Design (as-built).** `memory.enabled` defaults to `false`. When `false`: no SQLite database is opened, no compaction-event subscription runs, no `trim_history_search` tool is registered, no memory context hook is added, and existing Trim behavior is unchanged. A memory setup failure is isolated from Trim (memory is silently disabled). When enabled, the plugin observes `session.compaction.started` / `ended` / `failed`; it never performs or requests compaction and never generates or re-summarizes text. Only a readable `ended.text` string is archived; an empty or non-string `ended.text`, or an `ended` event carrying `native`, is skipped. The stored text is the original summary after secret [REDACTED] and a 1,000,000-character cap; text that is empty after redaction is skipped. There is no automatic per-message history scan; retrieval happens only on an explicit tool call. Store: Node 26 built-in `node:sqlite` with FTS5, local database only (no new dependency). Each row records project, session, model, reason, `created_at`, full text, bounded tokens/cost JSON (≤65,536 chars; malformed, oversized, cyclic, accessor, or non-plain values are stored NULL without failing the text archive), and `context_before_tokens` / `context_after_tokens` estimates. `event_id` dedupe is project-scoped (`UNIQUE(project, event_id)`; legacy databases auto-migrate, see §4h). A project filter is mandatory; sessions within a project share history by design. The stats observer in `plugin.js` stays weaker (first-usable candidate, missing = local) and is not a confidentiality boundary (see §4j). Default database path is `$XDG_DATA_HOME/opencode-trim/memory.db`, else `~/.local/share/opencode-trim/memory.db`; `memory.dbPath` must be absolute or `:memory:`. Estimates: `context_before_tokens` is estimated at `compaction.started` from `ctx.session.context()`; `context_after_tokens` stays `null` at `ended`, then the next `session.context` hook for that session fills it once. Both are estimates, not provider-reported usage; a `Compaction · 852.3K in · 3.5K out` line is the compaction request's usage, not context reduction. All checkpoints are retained (no deletion); on equal match strength, newer records from the same session are ordered first, while an older record with more distinct query-term hits stays ahead, so Next Move text in older checkpoints can be stale.

## 5. Remaining risks

1. **Prompt-cache effects are unmeasured.** Stable decisions reduce churn but no cache-hit guarantee is claimed.
2. **Estimated usage.** Byte/3 is conservative; exact provider counts require host telemetry not exposed to this hook.
3. **Compression is lossy for stored shell text.** No raw archive exists; `git diff/show/blame/apply` (plus `diff-index`/`diff-files`/`cherry-pick`/`format-patch`/patch-subflag variants), structured data, mixed media and binary payloads are passed through.
4. **Unknown tools stay unpruned.** This protects MCP/security results but leaves savings on the table.
5. **In-memory state.** Restart clears decisions; a new process may rewrite a prefix once.
6. **Provider-specific limits.** Custom providers missing from the catalog need an explicit `contextWindow`; otherwise only the absolute size budget applies.
7. **Plugin ordering.** A later plugin can rewrite the same result/context; last writer wins.
8. **Native and plugin-queued compaction may still summarize.** Native host compaction is host behaviour; in addition, when `autoCompact: true` (default) is enabled and post-prune primary context still meets or exceeds `usableTokens` with history beyond `protectRecentMessages`, `opencode-trim` queues a host compaction (`ctx.session.compact({ sessionID, delivery: 'queue' })`). Set `autoCompact: false` to disable plugin-initiated compaction triggers.
9. **Second-round and external-review host scope is narrow.** The §2c hardening is unit-covered plus the §4c refreshed check (400-row compression + read pruning only); the §2d follow-up is unit-covered plus the §4d refreshed check (plugin load + read pruning only); the §2e follow-up is unit-covered plus the §4e final check (load + read pruning only). Full coexistence, subagent, compaction and reload claims still rest on the earlier run, and no host-acceptance claim is made beyond §4e for the hardening cases; real-provider scope is stated in risk 17.
10. **Conservative `git branch` handling.** Only the allowlisted read flags stay eligible; other safe query spellings (for example an unlisted `--query`-style flag) under-prune rather than risk a write.
11. **Text-heuristic shell parsing.** `SAFE_SHELL` plus argv `mutatingArgs` is a syntactic heuristic, not a host permission check; compound or unusual invocations stay unpruned by design.
12. **Bounded pattern recognition.** Stack/path matchers and key/token [REDACTED] are length- and node-bounded against adversarial input; oversized values yield no key / raw output (safe under-pruning) instead of an unbounded scan.
13. **No provider token/cache telemetry.** Byte/3 estimates and replay stability are best-effort; exact usage, provider-side prompt-cache hits and restart-persistent pruning are unverified by design.
14. **Default path has no durable retrieval; optional `tool_vault` is bounded and secret-redacted (not lossless).** When `memory.enabled: false` (default), no database or raw-output archive exists and pruned/compressed outputs cannot be recovered through this plugin. When `memory.enabled: true`, the SQLite store holds redacted native compaction summaries (`trim_history_search`, §4g/§4h) and a bounded `vault` of pruned tool outputs (`trim_expand`, §4m): `saveVault` slices inputs at `1,000,000` chars (`MAX_TEXT_CHARS`), scrubs secrets via `redactSecrets` (failing closed through end-of-text on unclosed/over-depth structured secrets), evicts oldest entries past `500` rows per project (`maxVaultRows`), expires rows older than `retentionDays` (`90` days default, enforced at query time in `hasVault`/`getVault`/`listVault`), and `trim_expand` formats numbered lines capped at `maxChars` (`12,000` default, `200..50,000` max). Compressed `execute.after` outputs are never stored in `vault`.
15. **Bounded `plannedDrops` eviction.** Past `MAX_PLANNED=4000` the oldest planned ids are evicted in place; only results older than the newest retained drops can resurrect once after a long stable history.
16. **Read supersession is conservative by design.** OpenCode's read default is 2000 lines (`READ_DEFAULT_LINES=2000`): a no-limit read covers `start..start+2000`, never `Infinity` or a whole 5000-line read, so the external high-severity `readRange` claim is refuted. Nonsensical ranges yield no key and offset mismatches simply fail to supersede; the cost is conservative under-pruning, never over-pruning.

17. **Content-shape and real-provider scope.** The content-shape accessor fixes are unit-covered with no dedicated host run; the real-provider section covers npm-family shell compression and read pruning on that path only — coexistence, subagent, compaction, reload, token usage and cache-hit claims still rest on the earlier runs or remain NOT_RUN.

18. **Memory trusts host compaction payloads.** Archived text, reason, session/model identifiers, and tokens/cost JSON come from host `session.compaction` events; a compromised or buggy host (or another plugin rewriting the event) could plant misleading history. No provenance signature is checked. Location attribution is fail-closed for archiving (`started`/`ended` proceed only on local; absent/ambiguous/conflict/foreign rejected before any payload or archive work), while `failed` clearing and the `session.context` after-fill admit local or absent events (rejecting foreign/ambiguous/conflict). In `src/plugin.ts`, `foreignEvent(event)` short-circuits `tool.execute.after`, `session.context`, and `session.compaction` whenever an explicit foreign or malformed location is present on `e`, `e.data`, `e.properties`, `e.context`, or `e.session` (while treating location-less events as local).
19. **Memory authorization is hook-based and project-wide by design.** `execute.before` enforces the allow/denylist, but any agent the host exposes `trim_history_search` to can search all sessions in the active project. The lists hold at most 20 simple names and contain no hardcoded agents; an empty allowlist defers to host-native tool permissions.
20. **Memory redaction is best-effort, not a confidentiality boundary.** Pattern-based scrubbing (PEM, Bearer/Basic, JWTs, provider tokens, URL passwords, nested key/value assignments) runs before storage, but unknown, encoded, or high-entropy secrets may remain. Do not treat the archive as safe for secrets.
21. **Memory `event_id` scope (resolved in Phase 1.1, see §4h).** Dedupe was keyed by `event_id` alone, so two projects sharing one `dbPath` could collide on the same event id. Dedupe is now `UNIQUE(project, event_id)` — the same id archives once per project — and legacy databases auto-migrate on open.
22. **Memory physical deletion is outside plugin control.** Retention hides expired rows from search and deletes them on store open and after an accepted archive, but SQLite free pages, `VACUUM` behavior, filesystem/journal sidecars, and operator backups may retain bytes. Deletion is `rm -f <dbPath>*` with no recovery.
23. **Memory host coverage gaps.** Auto compaction after the final hardening, `compaction.failed`, and restart between compaction and the next turn (which fills `context_after_tokens`, NULL-surviving-restart per the in-memory pending-fill limitation) are now host-exercised (§4j), as is concurrent two-project sharing of one `dbPath` (fixed build ISOLATED, §4j); detached subscription-pump behavior under host backpressure remains unit-covered only. Earlier host acceptance did cover automatic archiving (reason `auto`) and the allow/deny path before the final hardening; disabled mode is host-verified (§4g, extended in §4j). The remaining Phase 1.1 gap is live native compaction (stated in §4h).
24. **Memory search scan ceiling.** Each search scans at most 1000 FTS rows / 8,000,000 characters under freshness ordering; candidates beyond the ceiling may be missed (§4h).
25. **Memory migration needs disk and the write lock.** The legacy-to-composite rebuild runs in one transaction with rollback and a 5 s busy timeout, but it still needs free disk space and the database write lock; a full disk or a concurrent writer fails the open instead of partially migrating (§4h).
26. **Snapshot-stability concurrency test gap.** Snapshot stability during search is enforced by a read transaction and closure behavior is tested, but no deterministic concurrent-interleaving test proves a writer cannot shift a snapshot mid-search (§4h).

27. **TUI visibility and remote surface (§4i–§4j).** Sidebar host-verified from 121 columns up (auto-show) and forced open via `Ctrl+X B` down to 80; trim content fits the 42-column sidebar with no clipping at 80/100/120/160/200. Real SGR mouse click toggled collapse/expand; the `matrix` theme changed colors with layout unchanged. Terminal fonts (terminal-side), a many-row long sidebar, and remote TUI not tested. RPC `opencode-trim-stats` relies on host auth and location scoping; it carries no project path, command, query, text, model, or summary by design, so a host auth/location bypass would expose only operational counters — that bypass itself is outside plugin control.
28. **TUI counters are ephemeral and approximate (§4i).** Live compaction counters remain in-memory per server process and reset on server restart (unchanged); when unknown, the TUI now derives a read-only fallback (`compact N archived` / `failed N` / `last <age> ago <auto|manual>`) from already-loaded persisted session compaction messages — not telemetry persistence, no new DB/state file, memory summaries stay separate. `N archived` scans only loaded messages (no pagination) and may undercount very long sessions. Snapshot clock skew or staleness may show outdated values. `auto events`/`manual events` are observed `ended` counts, not a host `compaction.auto` claim. Trim's byte/3 context estimate is a `~`-marked fallback to host-native usage, never provider-reported.
29. **TUI persistence and memory error surface (§4i).** The TUI persists only `expanded`; memory archive persistence is separate. Memory error-enum values surfaced through stats are display-only with no secret payload by design; unknown future enum values render as unknown. TUI/stats reviews were read-only passes in the same review context, not an independent external audit.
